# TomoTomo 要件定義書（v2：組織論）

- 版：2.0（2026-11-07）
- 位置づけ：アプリ全体の要件。`CLAUDE.md`（作業ガイド）、`docs/design-brief.md`（採用・組織づくりの設計書）を前提に、**組織論を軸に作り直す**ための要件を定める。食い違う場合はこの文書を優先する。
- 根拠資料：`docs/research/organization-theory.md`（調査ノート、`content/curriculum.json` から生成）
- 確認：各要件は末尾の「受け入れ基準（AC）」で確認し、結果を `docs/acceptance-check.md` に記録する。

---

## 1. 目的

組織論の**学術的な知見**（理論・実証研究・メタ分析・公的統計）を体系的に学び、**実務**（顧客への提案、社内研修、業務改善、経営判断）にそのまま使える形で身につける、自分専用のトレーナーにする。

- **学術的**：主張には出典と信頼度ランクを付ける。有名だが検証の弱い理論は、その旨を明示する。
- **実践的**：各単元で「どう使うか」を、立場別（コンサル・人事・経営など）と3つの視点（お客さん・教える・仕組み）で示す。
- **続けられる**：毎日10〜15分、「今日の学習をはじめる」を押すだけで始まる。

## 2. 利用者

| 利用者 | 特徴 | 主な使い方 |
|---|---|---|
| オーナー（主利用者） | 採用コンサル会社で業務改善・AI活用・社内教育を担当。経営者の視点も理解したい | 毎日の学習、提案・研修のネタ集め |
| 想定読者（教材の書き方の前提） | 採用コンサル、求人広告・媒体の営業、人材紹介、企業の人事、経営者 | 「立場別：明日からの使い方」で参照 |

個人用アプリ（1人で使う）。複数ユーザーの管理は対象外。

## 3. 決定事項（2026-11-07 オーナー回答）

| # | 論点 | 決定 |
|---|---|---|
| D1 | 範囲 | **組織論を軸に、採用も一部として扱う**（採用・選考・定着は「人と組織の出会い」として組織論の枠組みで扱う） |
| D2 | 毎日の教材 | **カリキュラム中心＋ニュースは補助**。毎日の教材はカリキュラムの単元を順に作る。新しい研究・ニュースは週1回のトレンド追記（PRで提案）で補う |
| D3 | サンプル3テーマ | **組織論の教材に差し替える**。お手本（形式と品質の基準）の役割は新しい教材が引き継ぐ。学習の記録（XP・履歴）は残す |

## 4. 範囲

| 対象 | 対象外（今回は扱わない） |
|---|---|
| 組織論カリキュラム（12章・37単元）と教材 | 採用市場の時事ニュースの毎日配信（週1回のトレンド追記に移す） |
| 毎日1単元の教材の自動生成と品質検査 | 産業・経済・テクノロジー一般の教材（10/20 に追加した7分野） |
| 週1回のトレンド追記（PRで提案） | ステップ3（ネイティブアプリ化・プッシュ通知） |
| 知識マップ・推薦・10分学習（既存の中核機能） | 複数ユーザー・ランキングの拡張 |

## 5. カリキュラム要件

| ID | 要件 |
|---|---|
| CR-1 | カリキュラムは `content/curriculum.json` で一元管理する。章（目的・前の章とのつながり＝役割・調査キーワード）と単元（鍵となる概念・出典）を持つ |
| CR-2 | 構成は12章・37単元：序章（根拠の読み方）、組織とは何か、組織構造とデザイン、組織と環境、人と組織の出会い（採用と組織社会化）、動機づけと仕事のデザイン、チーム、リーダーシップと公正、コミットメント・エンゲージメント・定着、組織文化と組織学習、組織変革、補章（日本の組織と雇用システム） |
| CR-3 | すべての単元に、調査で書誌と内容を確認した出典を1件以上ひも付ける。出典は信頼度ランク（A〜C）と「確認した内容」を持つ |
| CR-4 | 調査ノート（`docs/research/organization-theory.md`）はカリキュラムのファイルから生成し、手で書き換えない |

## 6. 教材（コンテンツ）要件

| ID | 要件 |
|---|---|
| CT-1 | 形式は既存の教材と同じ（30秒／3分／10分の解説、因果、多角的視点、実務応用、6形式の問題と解説、思考問題3種、よくある質問、知識ノード） |
| CT-2 | 3分の解説は「事実（研究で分かっていること）」「背景（理論の位置づけ）」「重要ポイント（実務での使い方・誤解）」の3ブロック。事実とAIの解釈を分ける |
| CT-3 | すべての問題と3分の解説の各ブロックに根拠（出典名・URL・信頼度ランクA〜C）を付ける。**ランクDは使わない**。ランクCだけの内容は確定した事実として書かない |
| CT-4 | 問題は専門家の検定試験の水準。記事の読み取りや常識で解ける問題にしない。誤答は実務者がよくする誤解にする。正解の位置は偏らない |
| CT-5 | 有名だが検証が弱い理論・モデル（例：レヴィンの3段階、コッターの8段階）は、その根拠の状態を明示する |
| CT-6 | 実践：立場別の使い方（採用コンサル・媒体営業・人材紹介・企業人事・経営者）と、**3つの視点**（お客さん視点・教える視点・仕組みの視点）を各教材に入れる |
| CT-7 | 教材は単元にひも付く（`unit`・`chapter`）。単元の出典（事前に確認済み）を事実の根拠の中心にする |
| CT-8 | サンプル3テーマを、組織論の教材3本（心理的安全性／組織社会化とオンボーディング／組織変革の3段階モデルの神話）に差し替える。これらが新しいお手本になる |

## 7. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| FR-1 | ホーム | 「今日のテーマ」は、今日配信された単元、なければカリキュラム順で次の未学習の単元を優先する。「今日の学習をはじめる」1回で始まる |
| FR-2 | 学習タブ | カリキュラム（章と単元）を表示する。単元ごとに「学習済み／学習できる／準備中」を表示し、学習できる単元だけにボタンを出す（準備中にボタンは出さない） |
| FR-3 | 章の情報 | 章ごとに役割（前後の章とのつながり）と進み具合を表示する。週1回のトレンド追記（マージ済み）があれば「最新トレンド（参考）」として章に表示する |
| FR-4 | 学習の流れ | ホーム → 学習 → クイズ → 思考問題 → 結果 → 知識マップ更新 → 次のおすすめ → 成長 の流れを維持する |
| FR-5 | 根拠の表示 | 解説と3分の解説に根拠とランクのバッジ、情報源にランクを表示する。出典がCだけの教材は「トレンド（参考）」と表示する |
| FR-6 | 3つの視点 | 「仕事への応用」で、立場別の使い方と3つの視点（お客さん・教える・仕組み）を表示する |
| FR-7 | 知識マップ | 組織論の5分野（組織デザイン／組織と環境／人と仕事／チームとリーダー／文化・学習・変革）で色分けし、カリキュラムの主要概念をノードとして持つ |
| FR-8 | AI | 思考問題の採点・ニュース対話（既存のAIサーバー経由、なければ簡易AI）を維持する |
| FR-9 | オンボーディング | 興味のあるテーマの選択肢を組織論の分野にする |

## 8. 教材づくり（自動生成）要件

| ID | 要件 |
|---|---|
| GN-1 | 毎朝1回、カリキュラムで**まだ教材のない次の単元**を1つ選んで教材を作る（ニュースの選定は行わない） |
| GN-2 | 単元の出典（事前に確認済みの内容）を調査メモの中心として渡す。追加の調査（Web検索・閲覧）は公的機関・国際機関・大学・学術出版社などに限り、実際に開いたページだけを使う |
| GN-3 | 品質検査は別の呼び出しで行い、出典・調査メモ・調査で開いたページの抜粋を材料にする（検査側でのページ閲覧に頼らない）。1項目でも不合格なら配信しない |
| GN-4 | 形式チェックは「全問に根拠」「3つの視点」「単元のひも付け」を必須にする |
| GN-5 | 1日の上限：教材づくりの試行は2回まで。Anthropic の残高が尽きたら止まる（それ以上の請求はない） |
| GN-6 | 週1回のトレンド追記は、カリキュラムの章とキーワードで調べ、関係する章への追記案を**PRで**出す。出典のない項目は機械的に除外する（既存の仕組み） |

## 9. 非機能要件

| ID | 要件 |
|---|---|
| NF-1 | 起動から学習開始まで3秒以内（ネットを待たずに表示。カリキュラム・教材は端末に保存したものを先に使う） |
| NF-2 | 一度開けばオフラインで学習できる（PWA） |
| NF-3 | 秘密情報（APIキー・合言葉）はリポジトリ・アプリに置かない |
| NF-4 | 既存の学習データ（`tomotomo:v1`）を壊さない。構造を変える場合は移行処理を書く |
| NF-5 | 費用：Anthropic の利用料のみ（月の目安は README に記載）。Cloudflare・GitHub は無料枠 |
| NF-6 | UIは日本語。スマホ（幅390px前後）で読みやすい |

## 10. データ移行要件

| ID | 要件 |
|---|---|
| MG-1 | 学習データのバージョンを2に上げる。旧サンプル3テーマの問題の復習予定は削除する（問題がなくなるため）。XP・履歴・連続日数・設定は残す |
| MG-2 | 旧サンプルの知識ノードの習熟度は残すが、マップには表示しない（存在しないノードは無視する。既存の防御） |
| MG-3 | 10/11〜10/28 に配信した7分野の教材は配信一覧から外す。すでに学習した教材は、端末の記録とともに残す（既存の仕組み） |

## 11. 受け入れ基準（AC）

| AC | 内容 | 確認方法 |
|---|---|---|
| AC-1 | カリキュラムが12章・37単元で、全単元に確認済みの出典（ランクA〜C）がある | 自動テスト |
| AC-2 | 調査ノートがカリキュラムから生成され、内容が一致している | 自動テスト（生成し直して差分なし） |
| AC-3 | 新しいお手本3本が形式チェック（根拠必須・3つの視点必須）に合格し、全問に根拠とランクがあり、Dがない | 自動テスト |
| AC-4 | お手本3本の出典が、すべてカリキュラムの確認済み出典（または公的統計）である | 自動テスト |
| AC-5 | 学習タブに章と単元が表示され、学習できる単元だけにボタンがあり、準備中にはボタンがない | 自動テスト（画面） |
| AC-6 | ホームの「今日のテーマ」がカリキュラム順の未学習の単元になる（今日の配信があればそれ） | 自動テスト（画面） |
| AC-7 | 学習の流れ（FR-4）を最後まで進められ、XP・知識マップが更新される | 自動テスト（画面） |
| AC-8 | 解説に根拠とランク、応用に3つの視点が表示される | 自動テスト（画面） |
| AC-9 | 知識マップが組織論の5分野で表示され、学習した概念のノードが出る | 自動テスト（画面） |
| AC-10 | 旧データ（v1、旧サンプルの学習記録あり）で起動しても壊れず、v2 に移行され、XP・履歴が残る | 自動テスト（画面） |
| AC-11 | オフラインで起動し、学習できる | 自動テスト（画面） |
| AC-12 | 教材づくりがカリキュラムの次の単元を選び、確認済みの出典を調査メモに入れ、根拠・3つの視点つきの教材を作る。不合格・調査不足は配信しない | 自動テスト（偽のAPI） |
| AC-13 | 週1回のトレンド追記が、カリキュラムの章で動き、出典のない項目を除外する | 自動テスト |
| AC-14 | 既存の自動テスト（アプリ・サーバー・教材づくり・トレンド）がすべて通る | 自動テスト |
| AC-15 | 画面を目で見て、表示崩れがない（ホーム・学習タブ・解説・応用・知識マップ） | スクリーンショットで目視 |

## 12. オーナーが行うこと

- Anthropic のクレジットを追加する（**2026-10-31 から残高不足で教材づくりが止まっている**）
- 週1回のトレンド調査の設定（Actions がPRを作れるようにする）。手順は README

## 13. リスク・未決事項

| # | 内容 | 対応 |
|---|---|---|
| R1 | 生成教材が品質検査に通りにくい（10月は不合格・調査不足が多かった） | 確認済みの出典を調査メモの中心に渡し、検査は材料を手元で渡す方式に変える（GN-2, GN-3）。それでも続く場合は検査基準を見直す |
| R2 | 書籍（ランクB）中心の単元は、追加調査で一次資料にたどり着きにくい | 書籍の要点は確認済みの範囲で使い、断定を避ける。教材では「学術書」と明示 |
| R3 | 効果量などの数値は要約経由で確認したものがある | 調査ノートに「要旨または信頼できる要約で確認」と明記。教材では数値の出典を必ず付ける |
| R4 | 旧サンプルを差し替えるため、旧サンプルで学んだ知識ノードはマップに出なくなる | MG-2。XP・履歴は残る |
