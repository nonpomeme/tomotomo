# 採用・組織づくり学習アプリ ブラッシュアップ設計書

> オーナーから受け取った設計書（PDF, 2026-10-28）を、リポジトリで参照できるよう文字に起こしたもの。内容は原文どおり。

## 1. 目的

採用コンサル会社で業務改善・AI活用・社内教育を担う立場から、次の3つを同時に実現する。

- **学ぶ**：採用と組織づくりの、根拠のある専門知識を体系的に身につける
- **活かす**：お客さん視点での提案、社内研修、業務改善に直結させる
- **更新し続ける**：トレンドや新しい研究を、正しさを確認したうえで継続的に取り込む

## 2. 全体構造：1本の軸と3つの視点

### 軸：人と組織のライフサイクル

教材は全体像から各論へ下りていく。各章の冒頭で「前の章とのつながり」「組織全体の中での役割」を必ず示す。

1. **組織の目的と人材要件**：事業戦略から、どんな人がどれだけ必要かを導く
2. **採用計画と母集団形成**：チャネル、採用ブランディング、候補者体験
3. **選考**：構造化面接、適性検査、ワークサンプルなど予測力のある手法
4. **オンボーディング**：入社後の受け入れと早期活躍、定着
5. **チームづくり**：心理的安全性、チームの成果を左右する要因
6. **評価と育成**：フィードバック、1on1、研修設計
7. **エンゲージメントと定着**：離職の要因と防ぎ方

### 3つの視点（各章で必ず扱う）

- **お客さん視点**：採用に悩む企業の経営者・人事担当は、この段階で何に困り、何を判断基準にしているか。コンサルが見落としがちな点は何か
- **教える視点**：この知識を社内研修にどう落とし込むか（ワーク、ケース、確認問題）
- **仕組みの視点**：この段階のどの作業をAIやシステムで改善できるか。どんなデータが扱われているか

### 補章：採用業界の構造

人材紹介、求人広告、ダイレクトリクルーティング、RPO、採用コンサルなどのビジネスモデルと、お金の流れ、各プレイヤーの強み弱みを整理する。各章の「お客さん視点」の前提知識として使う。

## 3. 各章のテンプレート

1. 全体の中での位置づけと前後の章とのつながり
2. 押さえるべき核心概念
3. 根拠（研究・データ）と信頼度
4. お客さん視点
5. 教える視点（研修ネタ、確認問題）
6. 仕組みの視点（AI・システム活用のアイデア）
7. 最新トレンド（自動更新の対象）
8. 出典一覧

## 4. 情報の信頼度ルール

根拠には次のランクを付け、問題や解説で表示する。

- **A**：メタ分析、査読付き論文、公的統計（厚生労働省、総務省、OECDなど）
- **B**：大手調査機関や学術機関のレポート、信頼できる業界団体の調査
- **C**：企業の調査、専門メディアの記事（参考扱い）
- **D**：個人の意見、SNS（教材の根拠には使わない）

トレンド情報はC以下になりやすいため、「トレンド」として明示し、根拠の章とは分けて扱う。

## 5. トレンドを正しくキャッチアップする仕組み

- **定期実行**：GitHub Actionsで週1回、Claude Codeを起動する
- **調査範囲**：章ごとのキーワードで、新しい研究、公的統計、主要な業界ニュースを調べる
- **出力**：関係する章への追記・修正案をプルリクエストとして作成。各項目に出典と信頼度ランクを付ける
- **人の確認**：みのさんが内容を確認してからマージする。勝手に本文が変わらない
- **活用**：毎回のプルリクエストに「今週の要点3つ」「お客さん・研修・業務改善への示唆」を添える

## 6. 進め方

1. 既存アプリの問題と解説を、上の7章と3視点に振り分ける
2. 足りない章・視点を洗い出す
3. 章ごとにリサーチ機能で根拠を集め、信頼度ランクを付ける
4. Claude Codeで問題・解説を修正し、出典を表示する
5. 自動更新の仕組みを入れる
